# Security Assessment — v3.1.0

**Assessor:** Lars (Larapilot Security Expert) — incorporates 🎯 Oliver red-team report (`red-team-v3.1.0.md`)
**Date:** 2026-11-14
**Verdict:** GO

## Summary

Deploy target: Cipi 5.7 on an Oracle Cloud ARM VM (app `heatmap`, branch `main`), reachable on its `sslip.io` hostname with Cipi basic auth **off** since 2026-10-26: the app's own sign-in is the only gate. No edge or WAF; Laravel log files only. Production runs v3.0.0.

v3.1.0 adds the Garmin Connect sync (US-022) and 27 extended run metrics from the CSV and the API (US-023):

- **A01 — holds.** The one new route, `POST /sync/garmin`, sits in the authenticated group: signed out it redirects to `/login` before the controller runs. It takes no id and no input and writes only into the signed-in owner.
- **A02 — new secret, handled.** `GARMIN_API_KEY` lives only in the host `.env` (empty in `.env.example`). The 24-hour access token is cached in the `file` store, never in SQLite, never logged.
- **A03 — holds.** Every extended metric is parsed by anchored, bounded patterns; `NaN`, `INF`, overflow, negative, formula, and markup values are stored empty (Oliver, probe 1). Mass-assignment guards on `source`, `garmin_activity_id`, and `user_id` unchanged. Titles still escaped.
- **A04 — holds.** Sync now: POST only, CSRF, throttle 3/min per user, and a lock against a parallel sync. The import keeps its throttle, 5 MB, and 5,000-row caps.
- **A05 — holds (to confirm on the host).** v3.0.0 host env: `APP_ENV=production`, `APP_DEBUG=false`, `LOG_LEVEL=warning`, `SESSION_SECURE_COOKIE=true`. Security headers present on every response.
- **A06 — PASS.** `composer audit --no-dev`: no advisory. `vendor-audit --gate` (OSV.dev, 231 components): **0 open, 0 waived**. `laravel/framework` moved to 13.42.0 (GHSA-63hm-g96r-2m2q) and `vite` to 8.3.8, which closes the six advisories waived for v3.0.0.
- **A07 — no change.** Sign-in, throttle, and forced first password change as in v3.0.0.
- **A08 — no change.** Deploys pull `main` over HTTPS; no token in the repository.
- **A09 — slightly better.** Every sync attempt is a `garmin_syncs` row (trigger, outcome, cause, counts), and a failed sync shows a warning on the dashboard.
- **A10 — reopened, closed by design.** The app calls out again, but only to a host and paths fixed in code; no user input reaches the URL.

Checks run locally on `release/3.1.0`: 721 tests, Pint, Larastan — all pass.

## Findings

### [Low] Sync now runs in the request

- **OWASP:** A04
- **Location:** `app/Http/Controllers/Garmin/SyncGarminNowController.php`
- **Risk:** a long first full-history read holds a worker; owner-only, throttled, locked.
- **Remediation:** none required; run the first read with `php artisan garmin:sync` on the host if the button is slow.

### [Low] `location_name` must never be printed raw

- **OWASP:** A03
- **Location:** `activities.location_name`
- **Risk:** text from the Garmin API; not displayed in this release.
- **Remediation:** any future view uses `{{ }}`.

### [Low] API key expiry

- **OWASP:** A07
- **Location:** host `.env` → `GARMIN_API_KEY`
- **Risk:** the sync stops when the key expires (30 days to one year); the dashboard says so.
- **Remediation:** the owner renews the key and updates the host env.

### [Info] Accepted risks unchanged

- No edge or WAF on a private single-owner instance.
- `SECURITY.md` and `security.txt` deferred while the instance is private.

## Ship Recommendation

**GO.** No Critical, High, or Medium finding; the dependency gate passes with nothing open or waived. Before the migration, copy the SQLite file aside; after the deploy, confirm the host env flags, that the scheduler cron exists, and that `GARMIN_API_KEY` is set before relying on the daily sync.
