# Security Assessment — v2.0.1

**Assessor:** Lars (Larapilot Security Expert) — incorporates 🎯 Oliver red-team report (`red-team-v2.0.1.md`)
**Date:** 2026-10-18
**Verdict:** GO — on the conditions below; the two Medium findings are accepted by the owner for this deploy (decision journal, 2026-10-18, topic `v2.0.1 ship gate`).

## Summary

Deploy target unchanged since v2.0.0 (decided 2026-10-17): custom VPS with Deployer, **private** (basic auth, VPN or IP allowlist), no edge or WAF, Laravel log files only.

v2.0.1 carries no application code change, so the v2.0.0 OWASP review of the code stands: OAuth state and allowlist (A01/A07), escaping (A03), CSRF (A01), no SSRF (A10), encrypted tokens (A02).

- **A05/A01 — closed.** The Larapilot dashboard, Boost and MCP are development-only. Oliver re-tested a `--no-dev` install of the tag: no `/larapilot/*`, Boost or MCP route, and every probed path answers 404 under `APP_ENV=local`.
- **A06 — dependency gate PASS.** `vendor-audit --gate` (OSV.dev, 231 components): no open vulnerability. The v2.0.0 Critical/High (shell-quote, source-map-js) and the commonmark Low are fixed. `composer audit` still reports CVE-2026-108082 in `symfony/http-foundation` (Medium, below).

## Findings

### [Medium — accepted] symfony/http-foundation 8.1.6 — CVE-2026-108082, ReDoS via the Cache-Control header

- **OWASP:** A06
- **Location:** `composer.lock`
- **Risk:** worker exhaustion from a client that can reach PHP, before routing and throttling.
- **Acceptance:** the host is private, so only clients past basic auth, VPN or the IP allowlist reach PHP. Update to 8.1.7 or later in 2.0.2.

### [Medium — accepted] `.env.example` defaults are development values

- **OWASP:** A05, A09
- **Location:** `.env.example`
- **Risk:** a host built from the example file shows debug pages and keeps one unrotated log. The Boost endpoint of the v2.0.0 finding is gone with `--no-dev`.
- **Acceptance:** the production values are set on the host (conditions below). The example file is hardened in 2.0.2.

### [Low — deferred to 2.0.2] Garmin import review page has no rate limit

- **OWASP:** A04 · **Location:** `routes/web.php:44`

### [Low — deferred to 2.0.2] No security headers; the import confirmation page can be framed

- **OWASP:** A05 · **Location:** `bootstrap/app.php`

### [Low — deferred to 2.0.2] No sign-out; a remember-me cookie is always issued

- **OWASP:** A07 · **Location:** `app/Http/Controllers/Strava/StravaCallbackController.php:124`

The owner chose on 2026-10-18 to fix these before deploy; that decision is superseded by the same-day choice to deploy v2.0.1 now and fix them in 2.0.2.

### [Info] Accepted risks unchanged

These remain accepted while the instance is private:

- open Garmin import;
- fallback athlete displayed publicly;
- public heart rate;
- Strava API Agreement display clause;
- SECURITY.md and security.txt deferred.

## Ship Recommendation

**GO for v2.0.1**, deployed only under these conditions on the custom VPS:

- `composer install --no-dev --optimize-autoloader`, then `php artisan route:list --path=larapilot` lists no route
- `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` on https
- `LOG_STACK=daily`, `LOG_LEVEL=warning`, `SESSION_SECURE_COOKIE=true`
- `php artisan optimize` after every deploy
- a cron entry running `schedule:run` every minute
- the SQLite file and `storage/` on persistent, non-public paths
- basic auth, VPN or an IP allowlist in front of the whole site

A public deployment re-opens this assessment: the accepted risks above are acceptable only while the instance is private.
