## Lars (security)

- [Low] bootstrap/app.php — `SetSecurityHeaders` was appended last, so a response an earlier global middleware ends the request with (503 in maintenance, 413 for an oversized upload) skipped it.
- [Low] app/Http/Middleware/SetSecurityHeaders.php — a weaker header set by a future controller or package would win silently; the values are constants, so there is no header injection or cache poisoning.
- [Low] app/Http/Middleware/SetSecurityHeaders.php, bootstrap/app.php — no `trustProxies` is configured, so behind a TLS-terminating proxy HSTS is never sent and all guests would share one throttle bucket (the proxy's IP). Settle it with the deployment, before ship.
- Clean: no cross-visitor or cross-athlete leak through the remembered plan (ids and a hash only, stored runs reloaded fresh for the resolved athlete); a guest sees no more of a stored run than before; the confirm still plans fresh under its lock; `composer audit` reports nothing and no dependency was added.
