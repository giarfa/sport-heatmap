# US-008 — Review: Import runs from a Garmin Connect CSV with conflict review

Branch `feature/US-008-garmin-csv-import` → `develop` (not pushed — `git_mode: GITFLOW`).
Full suite: 339 tests passed; `larapilot:quality` (Pint + Larastan level 5) clean;
`migrate:fresh --seed`, and the new migration's rollback and re-run, verified.

## Robert (code review)

- [Medium] `PlanGarminImport` claimed stored runs in file order, so "closest wins" could fail when two CSV rows competed for one stored run: an earlier row 90 s away took it, and the exact match was planned as new. A Skip then left that run on the map twice. The same first-come claiming exists in late-twin linking in `ReconcileStravaWindow`.
- [Medium] A double-submitted "Confirm import" could insert the new runs twice. Both requests carry the same pending session, every check runs before either commits, and Garmin-new rows have no unique key.
- [Low] Rows identical within one file collapse silently and are counted under no heading.
- [Low] `GarminCsvColumns` picked the language from the first header cell only, which contradicted its own "by name, never by position" note.
- [Low] The window and the future cutoff are fixed at upload and not re-checked at confirm.
- [Low] The owner's real Garmin export, with heart rate, cadence and place names, is committed as client material and copied as a test fixture.
- [Low] The `ReconcileStravaWindow` comment justified `forceFill` with "identity column", but `strava_activity_id` is fillable.
- [Low] A malformed distance (`"8,29 km"`) was reported as "missing distance".

## Lars (security)

- [Medium] There was no row cap. 5 MB of minimal rows (~100k) would all go into the session and into an O(rows × stored) plan on every review and confirm. Ignored-type labels and the invalid list were also unbounded.
- [Medium] Real personal health and location data (the client export plus the fixture copy) is in git history, and the remote is on GitHub.
- [Low] An unbounded distance (`"99999…"`) overflowed the int cast into a negative distance, and the moving-time hour group was unbounded too.
- [Low] Parsed rows sit unencrypted in `sessions.payload` (`SESSION_ENCRYPT=false`) until confirm, cancel, the next upload or expiry.
- [Low] Only `store` was throttled; `review` and `confirm` repeat the plan with no limit.
- [Low] Ignored type names are echoed back on the summary. They are escaped, so this is not XSS, but they had no length cap (same root cause as the row-cap finding).
- [Low] `league/commonmark` advisories (GHSA-3q6v-r5mr-hxv8 and one medium) predate this branch and are not reachable from the app; run `larapilot-vendor-check`.
- Verified clean: `auth` + `strava.fresh` on every route; CSRF on upload, confirm and cancel; pending rows bound to the session only; `hash_equals` on token and fingerprint; plan recomputed at confirm; forged `resolutions` indexes do nothing; file never `store()`d; binary and non-UTF-8 input rejected; no `{!! !!}`; `source` only ever set server-side; Strava links only on Strava-sourced rows; the sync deletes `source = strava` rows only.

## Parent actions

- Fixed (`f0da786`):
  - **Closest pairs first:** CSV rows are now paired with stored runs closest-first across the whole file (`StartTimeMatcher::difference()`), with a regression test.
  - **Double submit:** confirm runs under a per-owner `Cache::lock`, so a second submit re-plans after the first commits, fails the fingerprint and writes nothing. Confirm is now throttled too. Regression test added.
  - **Upload caps:** 1,000 in-window runs, 100 unreadable rows, 50 distinct ignored types, 60-character type names.
  - **Distance:** at most six integer digits and four hour digits; a malformed distance is now reported as "unreadable distance".
  - **Header language:** detected by name (the type header plus all but one required header), so Strava's export is still rejected.
  - **Stale comment:** corrected, and `forceFill` replaced by `fill`.
- Resolved at review (decision `9f72c0d14a487bec`): the repository is public, so the real Garmin export (`.larapilot/client-materials/Activities (1).csv`, `tests/Fixtures/Garmin/activities-it.csv`) was anonymised before the first push. Place names became `Paese` / `Valle` / `Monte`. Heart rate, cadence, calories, elevation, steps and running dynamics became `--`. The unpushed US-008 history was rewritten, so the originals never reached the remote.
- Open (Low):
  - Late-twin linking in the sync still claims in fetch order. It needs two Strava activities within ±2 minutes of one Garmin run, which is very rare.
  - In-file duplicates are not counted.
  - The window is fixed at upload.
  - Parsed rows sit unencrypted in the session (documented in `garmin-csv-import.md`; set `SESSION_ENCRYPT=true` if the store is shared).
  - The review GET is not throttled.
  - commonmark advisories (vendor check).
- Recommended: an **Oliver** red-team pass on the upload path before ship (a file import).
