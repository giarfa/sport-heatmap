## Robert (code review)

- [High] `app/Http/Middleware/EnsureFreshStravaToken.php:29` — the allowlist was never re-checked after login. `AthleteAllowlist` was consulted exactly once, in the callback; the session and the `remember: true` cookie minted at `StravaCallbackController.php:81` then survived indefinitely. Removing an athlete from `STRAVA_ALLOWED_ATHLETE_IDS` — which the README calls "the only access control in this product" — did not revoke their access.
- [Medium] `app/Http/Controllers/Strava/StravaCallbackController.php:36` — the `access_denied` branch flashed `status`, but no view rendered it. - [Medium] `app/Actions/Strava/EnsureFreshAccessToken.php:48` — the refresh was unserialised. Strava rotates the refresh token on every call, so two concurrent requests both seeing an expired token issued two refreshes; the loser persisted a token Strava had already invalidated, dead-ending the athlete on the reconnect screen with no way back except full re-authorization.
- [Low] `app/Http/Controllers/Strava/StravaCallbackController.php:33` — gate 1 returned before gate 2's `session()->pull()`, so a callback carrying `error=access_denied` left `strava.oauth_state` live and replayable. The state was single-use on every path except that one.
- [Low] `app/Exceptions/Strava/StravaReconnectRequiredException.php:22` — `render()` mutated global state (`Auth::logout()`, `session()->invalidate()`, `regenerateToken()`). Exception rendering is not guaranteed to be a single side-effect-safe call; the logout belongs in the middleware that catches the failure.
- [Low] `app/Actions/Strava/EnsureFreshAccessToken.php:43` — a synthetic `expiresAt: CarbonImmutable::now()` was stuffed into the DTO purely to satisfy the constructor.
- [Low] `app/Services/Strava/StravaOAuth.php:79` — no explicit `timeout()`/`connectTimeout()` on the token endpoint, so a Strava stall held the athlete for Laravel's 30s default before the rejection screen. `EnsureFreshStravaToken` inherited the same stall on the dashboard route.
- [Low] `app/Services/Strava/StravaOAuth.php:96` — `is_scalar()` accepted `true`/`false` for `expires_at`, which `StravaTokens.php:47` cast to epoch 0/1 and stored as a 1970 expiry, silently forcing a refresh on every request instead of raising `malformedTokenResponse`.

## Lars (security)

**No Critical and no High findings.** `composer audit` clean; this branch adds no new dependencies.

- [Medium] `app/Http/Controllers/Strava/StravaCallbackController.php:41` — `(string) $request->query('state', '')` (same at `:48` `scope` and `:61` `code`) cast a query parameter an attacker can supply as an array (`?state[]=x`). Laravel's `HandleExceptions` promotes the resulting "Array to string conversion" warning to an `ErrorException`, so any unauthenticated request could force a 500 on the callback — and with `APP_DEBUG=true` that renders a stack trace.
- [Medium] `app/Services/Strava/StravaOAuth.php:79` — `Http::asForm()->post()` throws `ConnectionException` on DNS/TLS/timeout failure, which is not a `StravaOAuthException`. It escaped both catch blocks that existed for this purpose (`StravaCallbackController.php:62`, `EnsureFreshAccessToken.php:49`) and surfaced as a 500 — directly violating the "refresh failure surfaces as a reconnect state, not a 500" criterion. Tests only used `Http::fake()`, so the path was uncovered.
- [Medium] `app/Actions/Strava/EnsureFreshAccessToken.php:30` — reading `$user->strava_refresh_token` after an APP_KEY rotation (or a restore into an environment with a different key) threw an uncaught `DecryptException`. Because `strava.fresh` is on the `/` route, every dashboard load 500'd with no in-app recovery path.
- [Medium] `app/Http/Controllers/Strava/StravaCallbackController.php:51` — the scope gate only asserted that the granted scope *contained* `activity:read_all`; it never rejected surplus scopes. An athlete who hand-edits the `scope` parameter on Strava's consent URL could grant `activity:write`, and the app would persist a write-capable token. The "no write scope" invariant was enforced on the request side only.
- [Medium] `.env.example:30` — `SESSION_SECURE_COOKIE` absent, so neither the session cookie nor the 5-year remember-me cookie issued by `Auth::login($user, remember: true)` carried the `Secure` flag. The README documents HTTPS for the callback but never told the operator to set this.
- [Low] `app/Http/Controllers/Strava/StravaCallbackController.php:85` — `redirect()->intended(route('dashboard'))` pulls `url.intended` from the session, and an absolute URL passes through the generator untouched. Nothing writes `url.intended` today, so it was latent rather than live — but it becomes a post-login open redirect the moment `auth` middleware or `redirect()->guest()` is added.
- [Low] `app/Http/Controllers/Strava/StravaCallbackController.php:71` — on allowlist rejection the freshly minted tokens are dropped in memory but never revoked, so they remain live on Strava's side (~6h access, indefinite refresh). The "no tokens stored" criterion is met; this is about tokens that were issued.
- [Low] `app/Providers/AppServiceProvider.php:35` — the limiter keys solely on `$request->ip()` and `bootstrap/app.php` never calls `->trustProxies(...)`. Behind a reverse proxy every request presents the proxy address, collapsing the 10/min budget into one shared bucket.
- [Low] `app/Http/Controllers/DashboardController.php:19` — access control on `/` is a ternary inside the controller rather than route middleware. Correct today because `dashboard.blade.php` holds no data, but US-004 onward adds real activity data to that view.
- [Low] `resources/views/layouts/app.blade.php:8` — no `Referrer-Policy`, `X-Frame-Options`/CSP `frame-ancestors`, or CSP on any response. The callback URL carries the authorization `code` in its query string.
- [Low] `.env.example:4` — ships `APP_DEBUG=true` with no production note in the README deployment section. Combined with the 500 paths above, this turned an internet-reachable callback route into a stack-trace disclosure.
- [Low] `SECURITY.md` / `public/.well-known/security.txt` — absent. Defensible for a private single-athlete instance; revisit at ship.

**Verified as sound by Lars, for the record:** state is a 40-char `Str::random` CSPRNG value, session-bound, single-use via `pull()`, compared with `hash_equals`; the allowlist gate runs before any write and fails closed on an empty list; the session is regenerated on login; the Strava columns are excluded from `#[Fillable]` and included in `#[Hidden]`; the `encrypted` casts are correctly applied to both token columns; exception messages carry only HTTP status and missing key names, never response bodies; `.env` and `bootstrap/cache/` are gitignored, so a `config:cache` run cannot commit the client secret.

## Parent actions

Commit `ee942b0` — `fix(US-002): address Robert and Lars review findings`.

**Fixed — High:**

- Allowlist re-checked on every authenticated request. `EnsureFreshStravaToken` now owns both gates in order: allowlist first, token freshness second. A revoked athlete gets the rejection screen and their session plus remember-me cookie are torn down on the spot. Covered by `test_removing_an_athlete_from_the_allowlist_ends_their_session_immediately` and `test_a_session_without_an_athlete_id_is_turned_away` (the null-athlete-id case fails closed).

**Fixed — Medium:**

- Array-shaped query parameters no longer reach a string cast. `queryString()` and `pullExpectedState()` treat a non-string as absent; covered for `state`, `code`, `scope`, and `error`.
- `ConnectionException` is wrapped as `StravaOAuthException::tokenEndpointUnreachable()`, so a network failure lands on the rejection screen (callback) or the reconnect screen (dashboard) rather than a 500. The chained exception's message is deliberately not reused — Guzzle embeds the request URL. Explicit `connectTimeout(5)`/`timeout(10)` added.
- `DecryptException` on either token column is converted to `StravaReconnectRequiredException`, so an APP_KEY rotation renders the reconnect screen instead of 500-ing the only route in the product.
- Granted write scopes are refused before any exchange. The check is suffix-based (`:write`, `write`) rather than exact set equality, so a read scope Strava adds later is tolerated while an unknown write scope is refused by default. New `write_scope` branch on the rejection screen.
- Token refresh is serialised behind `Cache::lock('strava:refresh:{id}')` with a 15s block; the winner refreshes, the loser re-reads the row and finds the stored token. `LockTimeoutException` degrades to a reconnect rather than an exception.
- `SESSION_SECURE_COOKIE` added to `.env.example` with a comment, plus a **Before putting this on a real host** README table covering it alongside `APP_DEBUG`, `APP_ENV`, and trusted proxies.
- The cancellation notice is rendered on the connect screen (`role="status"`), so the flash is no longer dead code.
- The session-fixation test now compares the session id recorded on route entry (via a `web`-group test middleware pushed after the kernel syncs its own groups) against the id captured inside the `Login` event — the boundary itself, not a redundant call. The redundant `regenerate()` was removed.

**Fixed — Low:**

- OAuth state is consumed on every path including cancellation; covered by `test_cancelling_consumes_the_state_too`.
- `StravaReconnectRequiredException::render()` removed; the middleware owns session teardown, leaving the exception a plain domain exception for the sync job in a later spec.
- `redirect()->intended()` replaced with the literal `redirect()->route('dashboard')`.
- `expires_at` validated with `is_numeric()`; the token strings validated as non-empty strings.
- A callback without a `code` is refused locally with a 400 rather than spending a round trip.
- The synthetic `CarbonImmutable::now()` expiry replaced with the stored expiry.
- `<meta name="referrer" content="same-origin">` added to the layout — the callback URL carries the authorization code in its query string.
- Plan YAML TASK-12 state committed.

**Open (Low) — deliberately not fixed:**

The spec's criterion ("no tokens stored") is met; the issued token expires in ~6h. Worth revisiting if the instance is ever internet-facing.
- **Trusted proxies not configured.** A deploy-topology decision, not a code one — belongs with `larapilot-ship` alongside the TLS and edge setup. Documented in the README meanwhile.
- **Access control on `/` is a controller ternary.** Correct as delivered; flagged forward to **US-004**, which is the spec that first puts real activity data on that view and should move the guard into route middleware.
- **No CSP / `X-Frame-Options` / `Referrer-Policy` response headers.** The meta referrer tag closes the code-leak path this spec introduced; a full header middleware is a project-wide concern for ship, not a US-002 deliverable.
- **`APP_DEBUG=true` in `.env.example`.** Also raised in the US-001 review. Left as-is because it is the file `composer setup` copies for local development; the README now states plainly what must change before a real host.
- **`SECURITY.md` / `security.txt` absent.** Same verdict as US-001: disclosure affordances for internet-facing services with third-party users. Revisit at ship.
