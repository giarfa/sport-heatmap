# Review — US-013 Previous / Next window navigation, with older Garmin runs kept

## Robert (code review)

- [Medium] `HeatmapGridCache::forgetAthlete()` bumped a missing counter with a `forever(…, 1)` fallback; two overlapping writes could both land on 1.
- [Medium] `forgetAthlete()` had no error handling, so a failing store would 500 an import that was already committed.
- [Medium] The `forgetAthlete` tests ran only on the array store, so the database store's missing-key branch was never exercised.
- [Low] `SyncStravaActivities` retired the cache only after every athlete reconciled; a later failure left earlier athletes' windows stale until the TTL.
- [Low] A legacy `outside_window` count was shown under the new "Future-dated" label.
- [Low] "16 weeks" / "4 weeks" are literals in `WindowNavigation` and the nav component, not read from `heatmap.window_weeks` / `navigation_step_weeks` (the grid's existing `h2` does the same).
- [Low] `$today` is part of every window's key, so past windows are rebuilt each midnight (correct, slightly wasteful).
- [Low] Branch hygiene: one commit per task with spec and task ids; domain docs current. No stale dev doc.

## Lars (security)

- [Medium] `?to=` accepts any past date and each week is a distinct cache key: a guest could fill the cache table with empty grids.
- [Medium] `PlanGarminImport` pairs every file row against every stored run on the file's dates; with the cap at 5,000 a full re-import is up to ~25M comparisons per request (throttle: 10/min/IP).
- [Low] A 5,000-row upload parks ~1–2 MB in the session payload.
- [Low] A signed-out visitor can now write up to 5,000 runs of any age into the displayed athlete (same trust model as US-011, wider reach); the rows are public through `?to=`, which matches the accepted public-dashboard risk, heart rate included.
- [Low] Generation counter reset on eviction could resurface an old entry for up to `grid_cache_ttl`; no cross-athlete exposure.
- [Low] `composer audit`: two advisories on transitive `league/commonmark`, unrelated to this story (no `composer.json` / lock change); belongs to `/larapilot-vendor-check`.
- [Low] No finding on query-string handling, cache-key construction, XSS, or the legacy session fallback.

## Parent actions

Fixed: the counter is created with `add()` then `increment()`; `forgetAthlete()` reports a store failure instead of throwing; the sync bumps per athlete as each is reconciled; the legacy `outside_window` key reads as 0; windows that end before the oldest run are built but not cached; first-bump and bump-twice tests run on the database store; a test pins which windows are cached; domain docs updated.

Open (Medium/Low): `PlanGarminImport` is quadratic in file size, so index `$stored` by date or lower the cap for signed-out imports (recommended before the 5,000 cap meets a hostile IP pool; the 5 MB limit and the throttle bound it today). The remaining Low items are accepted as written: session size, guest write reach (PRD-accepted trust model), counter eviction, hard-coded "16 / 4 weeks" copy, past windows rebuilt at midnight, and the unrelated `league/commonmark` advisories.
