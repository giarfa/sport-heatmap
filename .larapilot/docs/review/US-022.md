# Review — US-022 Automatic Garmin Connect sync (v3.1.0)

## Robert (code review)

- [Medium] app/Actions/Garmin/SyncGarminActivities.php — future-dated check used the server clock (UTC) instead of the runner's day; a run after local midnight could be skipped.
- [Low] SyncGarminActivities.php / ApplyGarminImport.php — the CSV import does not take the `garmin:sync` lock; a CSV confirm between the sync's candidate read and insert can leave an unlinked twin.
- [Low] SyncGarminActivities.php — a PHP timeout during Sync now skips `finally`, leaving a `running` row and a held lock for up to 30 minutes.
- [Low] app/Data/Garmin/GarminApiActivity.php — a metric Garmin later empties keeps its old stored value (deliberate: CSV-backfilled values survive).
- [Low] Gitflow — commit be61d54 is typed `fix` but only touches a test file.
- Pass: dev domain docs fresh, plan adherence, N+1 (one candidate query per page), `isDirty` on casts, 401 retry, failure mapping, factories and seeder.

## Lars (security)

- [Medium] Sync now runs a full-history sync in a web request (same finding as the timeout above).
- [Low] Unmapped HTTP client exceptions would reach `report()`; their messages can carry the request URL (never the key or token).
- [Low] Redirects were followed by default (Guzzle strips `Authorization` cross-host, so mitigated).
- [Low] The token file in `storage/framework/cache/data` follows the process umask.
- [Low] `composer audit`: 9 advisories in framework and symfony packages, none from this branch.
- Pass: no new dependency, no secret in the diff, `source` / `garmin_activity_id` not mass-assignable, bound queries, literal host, CSRF + auth + throttle on `POST /sync/garmin`.

## Manual test handoff (owner, with the real `GARMIN_API_KEY`)

1. Back up `database/database.sqlite`, then `php artisan migrate` (additive: `activities.source`, `activities.garmin_activity_id`, `garmin_syncs`). Never `migrate:fresh --seed` on this database.
2. `php artisan garmin:sync`: check the counts and that CSV-imported runs were linked, not duplicated. Run it again: new, updated and linked are all 0.

5. Add the scheduler cron entry on the Cipi host (`* * * * * cd {app} && php artisan schedule:run`) and check `php artisan schedule:list`.
