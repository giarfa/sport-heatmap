# v3.1.0 — Garmin Connect sync

Your runs now arrive from Garmin Connect on their own: once a day, and whenever you press **Sync now**.
The CSV import stays, and every run — synced or imported — keeps the richer values Garmin records,
ready for later views. With no Garmin key configured, the heatmap behaves exactly as before.

**Before you upgrade: back up the database.** The migration only adds empty columns and keeps every run,
but a backup is the safe way to roll back.

## Added

- **Automatic Garmin Connect sync.** With a personal API key in `GARMIN_API_KEY`, your running
  activities are read from Garmin Connect every day at 05:00 (your display timezone). The first sync
  reads your whole history; later ones re-read the last seven days, so a renamed run is updated. A run
  you already imported from a CSV is linked, not duplicated, and syncing twice changes nothing.
- **Sync now**, under the map and on the empty screen, with a summary of what the sync did.
- **A warning when the sync fails** — "Garmin key rejected — renew it", "Garmin unreachable", or
  "Garmin sync failed" — shown above the map until the next sync succeeds.
- **`php artisan garmin:sync`** to run the sync, or the first full-history read, from the command line.
- **Richer run data.** Each run keeps calories, max heart rate, training effect, cadence, best pace,
  descent, running form, steps, laps, elapsed time, elevation range, and Training Stress Score from a
  CSV export — Italian or English — plus heart-rate zones, fastest splits, and the location from the
  sync. A value Garmin did not record stays empty, never zero. Nothing new is shown on the dashboard yet.
- **Enriched runs on re-import.** Re-importing an older export fills in the values your stored runs
  lack, without asking about conflicts, and the import summary counts those runs as **Enriched**.
  Importing the same file again changes nothing.

## Changed

- **One status line for both sources.** It shows the more recent of "Last sync N ago" and "Last import
  N ago", and the card in the rail gains a "Last sync" row — only when a Garmin key is set.
- **The CSV import is one of two ways a run enters.** Overwriting a synced run with a CSV row keeps its
  link to Garmin.
- **No key, no change.** Without `GARMIN_API_KEY` there is no Sync now, no sync status, no warning, and
  nothing scheduled calls out.

## Security

- The framework and the build tool are updated to versions that close the known advisories against
  them. No dependency check reports an open vulnerability for this release.

## After upgrading

- Run the database migration; it adds the sync history table and new run columns, and keeps every
  stored run.
- To turn the sync on, set `GARMIN_API_KEY` and add the scheduler's cron entry on the host (see the
  README). Then press **Sync now** once to read your full history.
- Re-import your latest Garmin CSV export once to fill in the richer values of the runs you imported
  before.
